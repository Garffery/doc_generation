# 数据持久化规范

## 存储选型决策

撰写后端开发文档时，在「数据持久化方案」章节中**必须先判定存储载体**，再给出字段映射。不要混用两种模式。

| 场景 | 存储位置 | 判定依据 |
|------|----------|----------|
| **运营活动** | `#player_misc_extra{}` | 限时活动、赛季战令、节日玩法等；活动结束后数据可清理或归档；同一玩家可有多条记录（按 `key` 区分活动） |
| **功能 / 系统能力** | `#role{}` 中的字段 | 常驻功能（背包扩展、成就、VIP 等级等）；数据随角色长期存在；支持 Erlang 任意数据类型 |

**不确定时**：在文档中写明两种方案的取舍理由，并标注 **待确认**。

---

## 运营活动存储：`#player_misc_extra{}`

活动数据按 `(player_id, key)` 定位；`key` 一般为活动 id。

```erlang
#player_misc_extra{
    player_id,         %% 玩家id
    key,               %% key，一般是活动id，用来区分不同活动的数据
    value = 0,         %% 只支持数字，默认值为0
    value1 = 0,        %% 只支持数字，默认值为0
    value2 = 0,        %% 只支持数字，默认值为0
    value3 = 0,        %% 只支持数字，默认值为0
    value_text = [],   %% 默认值是一个list，list内部支持erlang中所有的数据类型
    value_text_1 = [], %% 默认值是一个list，list内部支持erlang中所有的数据类型
    value_text_2 = [], %% 默认值是一个list，list内部支持erlang中所有的数据类型
    value_text_3 = [], %% 默认值是一个list，list内部支持erlang中所有的数据类型
    time = 0,          %% 时间戳
    time1 = 0,         %% 时间戳
    time2 = 0,         %% 时间戳
    server_id = 0      %% 服务器id
}
```

### 字段分配原则

1. **数字类**（等级、积分、计数、位图掩码等）→ `value` / `value1` / `value2` / `value3`
2. **复杂结构**（奖励列表、任务进度 map、已领取档位列表等）→ `value_text` / `value_text_1` / `value_text_2` / `value_text_3`（list 内可放任意 Erlang 项）
3. **时间类**（活动开始/结束、上次刷新、结算时间等）→ `time` / `time1` / `time2`
4. 同一活动内**固定语义**的槽位须在文档中列表说明，禁止不同模块复用同一槽位

### 文档中必须写清

- `key` 取值规则（活动 id 或配置表 id）
- 各 `value*` / `value_text_*` / `time*` 的业务含义（使用表格说明）
- 活动结束后的数据策略（保留 / 删除 / 邮件补发后清理）

### 文档输出格式

```markdown
**存储选型**：运营活动 → `#player_misc_extra{}`

**key**：`<活动id 或规则>`

| 逻辑字段 | 物理位置 | 类型 | 说明 |
|----------|----------|------|------|
| xxx | value | 整数 | xxx |
| xxx | value_text | list | xxx |
| xxx | time | 时间戳 | xxx |

**生命周期**：活动结束后 <保留/删除/归档>
```

## 功能存储：`#role{}` 字段

常驻功能数据挂在玩家 `#role{}` record 的**具名字段**上。

### 使用规则

1. 数据类型：支持 Erlang 中所有数据类型（整数、元组、列表、map、嵌套 record 等）
2. 文档中须写清：**字段名**、**类型/结构示例**、**默认值**、**读写模块**
3. 若与活动共用逻辑，说明活动期内是否镜像到 `player_misc_extra`（一般不建议双写，除非有明确迁移需求）

### 文档输出格式

```markdown
**存储选型**：功能 → `#role{}.<字段名>`

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| role.xxx | integer | 0 | xxx |
| role.xxx | list | [] | xxx |

**读写模块**：`mod_xxx`
```

---

## 禁止事项

1. 禁止在未判定存储选型的情况下直接编写字段设计
2. 禁止将运营活动数据写入 `#role{}` 字段（造成数据膨胀且无法按活动清理）
3. 禁止将常驻功能数据写入 `#player_misc_extra{}`（槽位有限且语义不清晰）
4. 禁止同一活动的数据分散在多个 `key` 中，除非有明确的业务隔离需求
5. 禁止复用其他活动已占用的 `value*` / `value_text_*` / `time*` 槽位语义
