## 系统容错与容灾流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            容错机制 (Resilience)                             │
└─────────────────────────────────────────────────────────────────────────────┘

1. 重试机制 (Retry)
   ┌─────────────┐
   │  LLM 调用   │
   └──────┬──────┘
          │ 失败 (5xx / timeout)
          ▼
   ┌─────────────────┐
   │ 指数退避重试     │
   │ max_attempts: 3 │
   │ base_delay: 1s  │
   │ max_delay: 30s  │
   └──────┬──────────┘
          │ 仍失败
          ▼

2. 熔断器 (Circuit Breaker)
   ┌─────────────────────────┐
   │ 短期高频失败检测         │
   │ failure_threshold: 5    │
   │ recovery_timeout: 60s   │
   └──────┬──────────────────┘
          │ 熔断触发
          ▼
   ┌─────────────────┐
   │ 停止调用 60s    │
   │ 半开状态尝试    │
   └──────┬──────────┘
          │
          ▼

3. LLM 降级链 (Fallback Chain)
   ┌──────────────────┐
   │ OpenAI (主链)    │
   └────────┬─────────┘
            │ 失败
            ▼
   ┌──────────────────┐
   │ DeepSeek (备链)  │
   └────────┬─────────┘
            │ 失败
            ▼
   ┌──────────────────┐
   │ 静态响应 (兜底)  │
   └──────────────────┘

4. MongoDB Checkpoint (断点恢复)
   ┌─────────────────────────┐
   │ 进程崩溃 / 网络断开      │
   └──────┬──────────────────┘
          │
          ▼
   ┌─────────────────────────┐
   │ POST /api/retry         │
   │ - thread_id 检索状态    │
   │ - MongoDB 恢复 checkpoint│
   │ - 从断点继续执行        │
   └─────────────────────────┘
```

## 数据流与存储

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              数据存储架构                                    │
└─────────────────────────────────────────────────────────────────────────────┘

1. MongoDB
   ├─ doc_generation (主图 checkpoint)
   │  └─ thread_id → GraphState
   ├─ doc_generation_researcher (研究子图 checkpoint)
   │  └─ thread_id → ResearcherState
   ├─ tickets (任务工单)
   │  ├─ ticket_id
   │  ├─ thread_id
   │  ├─ status: pending/running/done/error
   │  └─ query: 用户输入
   └─ reports (文档记录)
      ├─ ticket_id (关联)
      ├─ research_brief
      ├─ draft_report
      └─ final_report

2. Redis
   ├─ ARQ 任务队列
   │  └─ arq:queue (Claude Code 异步任务)
   └─ Claude Code 结果缓存
      ├─ claude_code_job:{job_id} → result
      └─ claude_code_job:{job_id}:error → error_msg

3. ChromaDB (向量数据库)
   └─ collection: doc_generation
      ├─ embeddings (BGE-M3)
      └─ documents (SKILL.md 内容)

4. 文件系统
   ├─ skills/public/{skill_name}/SKILL.md (领域知识文档)
   ├─ logs/backend.log (后端日志)
   └─ logs/agent_error.log (Agent 错误日志)
```

## 关键技术点

1. **LangGraph StateGraph**: 状态机编排多智能体工作流
2. **MongoDB Checkpoint**: 支持 interrupt/resume 跨进程恢复
3. **Send 并行派发**: Supervisor 通过 Send 实现 hand-off 状态隔离
4. **ARQ + Redis**: Claude Code 异步执行，避免阻塞主流程
5. **结构化输出**: with_structured_output() 强制模型返回 Pydantic 对象
6. **RAG 检索增强**: ChromaDB + BGE-M3 向量化领域知识
7. **Skills 可插拔注入**: 配置化领域知识注入到特定 Agent 节点
8. **容错机制**: 重试 + 熔断 + 降级链 + 静态兜底
9. **SSE 流式**: FastAPI astream_events() 实时推送执行进度
10. **对抗性审查**: Red Team + Evaluator 多轮质量评估与修复
